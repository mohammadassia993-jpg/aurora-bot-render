# RENDER_USAGE_ANALYSIS.md — تحليل استهلاك Render

## ملاحظة منهجية
لوحة تحكم Render غير قابلة للوصول برمجياً من هذه البيئة (لا API token متاح).
تم إجراء التحليل على مستوى الكود: تعداد جميع العمليات النشطة والمسارات التي تستهلك موارد.

---

## 2. المهام المجدولة (cron)

| التوقيت | المهمة | الوزن |
|---------|--------|-------|
| 05:00 يومي | توليد حزمة 92 مهام | **ثقيل (AI calls)** |
| 06:00 يومي | فحص الفرص | متوسط (شبكة + AI) |
| 10:00/16:00/04:00/22:00 | 4 تقارير يومية | منخفض |

## 3. الحكم: هل 512MB كافية؟

**نعم، 512MB كافية للتشغيل الأساسي** (Node + SQLite WAL + Telegram + HTTP server ≈ 150-250MB).
لكنها **قد تتجاوز** عند:
- تشغيل AI calls متزامنة (كل استدعاء LLM يستهلك ذاكرة مؤقتاً)
- توليد حزمة 92 مهام (كثير من استدعاءات AI في حلقة)
- تنفيذ production/formatting (Puppeteer/PDF إن فُعل)

## 4. التطبيق الأكثر استهلاكاً
- **سلسلة الإنتاج (production.js)**: توليد محتوى + تحويل PDF (ثقيل)
- **Scheduler 05:00**: توليد حزمة 92 مهام (ثقيل)
- **Puppeteer/PDF conversion**: غير نشط حالياً لكنه الأعلى استهلاكاً إذا فُعل

## 5. الخلاصة
512MB كافية إذا بقي الإنتاج الثقيل معطلاً. التحسينات في RENDER_OPTIMIZATION.md تخفض الاستهلاك أكثر.
